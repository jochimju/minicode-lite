# 阶段 0-5 教学注释设计

## 目标

为 `minicode_lite/` 中阶段 0-5 已有的运行时代码补充简体中文教学注释，让学习者可以沿着代码理解 MiniCode Lite harness 的最小闭环。测试文件不在本次注释范围内。

## 范围

本次只修改以下内容：

- `minicode_lite/` 及其 `tools/` 子目录中的 Python 源码。
- `AGENTS.md` 中的持久化注释规范。

不修改测试文件的注释，不改变运行时行为、公开接口、工具输入输出或 CLI 行为。

## 注释层级

### 核心模块：逐逻辑行讲解

以下模块是学习 harness 主链路的关键位置，需要对每条有逻辑意义的语句添加中文注释：

- `types.py`：消息、步骤和模型适配器的共同契约。
- `tooling.py`：工具定义、工具上下文和执行时的错误转换。
- `agent_loop.py`：模型、工具、消息列表之间的循环与停止条件。
- `workspace.py`：工作区路径解析与越界保护。
- `tools/_shared.py`：文件工具共享的安全解析、读取和写入逻辑。

导入、空行、纯格式标记等没有独立语义的行不强行添加冗余注释；其余行解释数据如何流动、为什么要校验、状态如何变化或错误为何被转换为结果对象。

### 次核心模块：函数和关键分支讲解

以下模块中的每个函数、工具校验器、执行器和关键分支会有中文注释：

- `mock_model.py`
- `headless.py`
- `local_commands.py`
- `main.py`
- `tools/list_files.py`
- `tools/read_file.py`
- `tools/write_file.py`
- `tools/edit_file.py`
- `tools/patch_file.py`
- `tools/__init__.py`

重点解释输入规范化、工具定义注册、本地命令分流、单轮 headless 执行，以及文本编辑与补丁的安全限制。

### 辅助模块：职责和入口讲解

`__init__.py` 与 `__main__.py` 只需说明包版本导出和 `python -m` 入口职责，避免将简单代码注释得难以阅读。

## 注释写法

- 使用简体中文的行内注释与简短函数说明。
- 先说明原因和职责，再说明动作本身。
- 术语保留代码中的英文标识符，例如 `ToolResult`、`agent loop`，并给出中文语境。
- 不重复 Python 语法的表面含义，不写与代码不一致的注释。

## 后续约束

在 `AGENTS.md` 中加入规则：后续每个阶段新增或修改运行时代码时，必须加入简体中文教学注释。核心模块/函数逐逻辑行解释；非核心模块/函数至少解释职责、输入输出、关键分支和边界；测试文件不要求逐行注释。

## 验证

本次仅添加注释与规则，仍需运行完整 `python -m pytest -q`，确保注释编辑没有误伤语法或行为。完成后检查改动范围，并依项目现有 Git 规范提交、打标签和推送。
